# OpenCode 2.3.2 与 Pi 1.6.0 云沙箱升级验证

## 本机验证与设计依据

2026-11-21 在 macOS Intel、Node 24.19.0、Python 3.12.10 环境下运行真实版本。OpenCode V2 的旧健康路径返回 HTTP 200 和 HTML，带 Basic Auth 的 /api/info 才返回含版本的 JSON，无认证返回 401。创建会话和提交的结果嵌套在 data 中。两轮 DeepSeek 请求成功，消息接口按新到旧返回，终态有 outcome；/api/event 的事件属性在 data 中。使用可控模型响应补测了两轮会话的消息归属。

Pi 1.6.0 用现有桥接和真实 DeepSeek 跑过 shell、用量、续聊、中止、运行中重载。原生 MCP 使用 exposure=direct。在独立 HOME 中，原桥接的 -ne 会一并关闭内置扩展，导致模型收不到用户级 MCP 工具；只删除这个参数后，真实 Pi 首轮执行了本地 stdio MCP 工具，并完成后续两轮和运行中止。此对照实验的模型端由本机测试服务提供。真实百炼端点单独完成 initialize、tools/list 和 bailian_web_search 调用。

## 实现与验收顺序

1. 两份独立的 Gen2 FC 模板使用本地域官方 code-interpreter-v1:v0.0.52。OpenCode 锁定 Linux x64 制品并校验完整性。Pi 锁定 npm 发行包，使用其原生 MCP，保留普通用户、隔离工作目录、项目资源信任约束和平台 CA。旧模板保留作对照。
2. OpenCode V2 前台服务需要独立实例密码。在空模板中预装程序，等待实例装配文件，再启动进程；快照就绪检查验证安装，实例就绪检查验证 /api/info 返回的实际版本。云端使用 FC 入口令牌和应用认证，模型及 MCP 凭证通过域名出网规则注入。Pi 在模板内启动桥接，实例装配写入模型与 MCP 配置。
3. 先从两个模板各建真实隔离沙箱，验证版本、认证、会话、真实模型、工具、续聊和中止。单独标注模板原生端点的验证与经过业务网关的回归。基线 Python 与 Node 回归使用仓库测试替身。
4. 网关升级涉及 OpenCode 的建会话、model/agent 设置、prompt 受理、interrupt、分页消息、流式事件与配置重载；保留任务所有权、跨副本跟进与轮次校验。每个组件的验收范围据实记录。
5. 记录测试实例，验证结束终止测试进程、回收实例并重新列举目标账号/地域（包括暂停实例）。模板是复用产物。开始前列表为空。

官方参考：[OpenCode 迁移](https://opencode.ai/docs/migrate-v1/)、[V2 API](https://opencode.ai/docs/api)、[Pi 1.6 RPC](https://github.com/earendil-works/pi/blob/v1.6.0/packages/coding-agent/docs/rpc.md)、[Pi MCP](https://github.com/earendil-works/pi/blob/v1.6.0/packages/coding-agent/docs/mcp.md)、[FC 模板](https://help.aliyun.com/zh/functioncompute/build-a-custom-image-template)。

上述 ID 对应 FC 二代模板。OpenCode 选用 SHA-512 校验的 Linux x64 baseline 包；Pi 使用 Node 24.19.0、Pi 1.6.0 和桥接 0.2.0。配置研究环境时，将两个 ID 分别赋给表内变量，设置 `POOL_AGENT_ENABLED=true` 和 `POOL_AGENT_DEFAULT_ENGINE=opencode2` 或 `pi1`。开启旧版模板时，四个引擎可显式选择。数据库沿用已有引擎标识字段，同一任务从另一个副本接管时按该沙箱的记录匹配协议。

OpenCode 模板就绪时安装已完成。创建实例后，网关根据该实例的 FC 流量令牌计算专用应用密码，通过 envd 装配到实例再等待 /api/info。不同副本可使用同一实例密码。Pi 模板则以桥接进程的健康端点返回精确版本为就绪条件。两种引擎的模型和百炼授权都由平台按域名注入。

OpenCode 的 MCP 服务显式使用 `codemode=false`，网关可以收到直接工具名 `websearch_bailian_web_search`。Pi 的 `exposure=direct` 对应 `mcp__websearch__bailian_web_search`。两种引擎都以实际成功的工具事件验收搜索。

### 复现入口

以下命令在项目根目录运行。云模板操作需要加载本机云配置，真实搜索需要注入百炼授权。各轮使用独立测试池、SQLite 文件、调用方及管理员令牌；仅测 agent 时设置 `POOL_TARGET_SIZE=0`。完整网关配置见[业务接入手册](../2026-09-25-opencode常驻agent-业务接入使用手册.md)。

```bash
.venv/bin/python scripts/build_agent_research_template.py opencode
.venv/bin/python scripts/build_agent_research_template.py pi
.venv/bin/python scripts/verify_agent_research_template.py opencode <OpenCode模板ID>
.venv/bin/python scripts/verify_agent_research_template.py pi <Pi模板ID>
.venv/bin/python -m pytest -q
node --test sandbox_pool/agent/pi_bridge/test/bridge.test.mjs
```

用 `scripts/e2e_agent_scenarios.py --engine opencode2` 或 `--engine pi1` 跑常规 S1–S12，传 `--replicas` 指向专用的两个测试副本。S10 会终止第一个测试副本；PID 表必须对应本轮测试进程。S12 验证两个新版来回切换时，只配置两份新版模板。额外的 `--only S13,S11` 验证同一引擎旧版/新版的在途切换与回退，该轮同时配置对应旧版模板。S13 的任务从一个副本提交，在另一个副本读取终态。
