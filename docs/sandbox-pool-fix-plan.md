## 2. 修复原则

1. **不改变已确认的需求**：容量、排队、借用期限、归还即销毁、min_hot 默认 0 等保持不变。行为会变的地方（鉴权、同步归还、接管时不再一律销毁）都在本文和改动说明里写明。
2. **保持多副本安全**：新增的共享状态（保活时间、周期任务、排空开关）一律放在数据库里，用 CAS 或池级锁行协调，不引入选主，也不引入只在单副本成立的假设。
3. **每个问题至少一个针对性测试**：能用 FakeProvider 复现的都写成单元测试；依赖真实平台行为的（READY 保活、接管时查询实际状态、排空）再用端到端测试验证一次。
4. **兼容已有数据库**：新增的列都是可空列，启动时自动补齐（本地 demo 的轻量迁移；生产环境建议换 Alembic）。

## 3. 逐条修复方案

### 高

**H1　`min_hot` 保留的运行中沙箱约 3 分钟后被平台回收**
- 根因：READY 沙箱只在创建时设置过一次平台超时（空闲 60s + 120s），之后没有任何续期。
- 修复：
  - `sandboxes` 新增 `platform_deadline` 列，记录 READY 沙箱在平台上的到期时间。
  - 维护循环新增「READY 保活」：剩余时间不足一半时调用 `set_timeout` 续期。
  - **续期与借出的竞态**：保活的 `set_timeout`（短超时）可能比借用方的 `set_timeout`（借用期限 + 60s）晚到平台，把借出的沙箱超时改短。处理方式：
    1. 保活先用版本号 CAS 占住这一行，再调用平台。
    2. 调用返回后重新读这一行；如果期间被借走，就按借用剩余时间再设置一次平台超时。
    3. 借用方的 CAS 发生在重读之后时，它的 `set_timeout` 一定晚于保活到达平台，不需要处理。
- 测试：
  - `min_hot=2`、平台空闲超时 0.8s，运行 2s 后两个热沙箱仍是原来的 ID 且存活。
  - 构造「保活的 `set_timeout` 晚于借用方到达」的时序，结束后平台超时恢复为借用期限。

**H2　调试接口暴露 `lease_id`，接口没有鉴权**
- 修复：
  - **鉴权**：新增 Bearer Token 鉴权，两类 key：
    - `POOL_API_KEYS`（调用方），格式 `名称:key,名称:key`；
    - `POOL_ADMIN_KEYS`（管理员）。
    - 两者都不配置时关闭鉴权，只用于本地开发。
    - 此时 `python -m sandbox_pool` 拒绝监听非回环地址，除非显式加 `--allow-no-auth`。
  - **借用绑定调用方**：`leases` 新增 `client_id` 列。调用方只能查询、续期、归还、执行自己的借用，访问别人的借用返回 404（不暴露其是否存在）。管理员不受限制。
  - **调试接口**：`GET /v1/sandboxes` 只对管理员开放，且返回中去掉 `lease_id`。
  - key 比较使用常量时间比较；`/healthz` 不鉴权（负载均衡探活）。
- 测试：无 key / 错误 key 返回 401；调用方访问他人借用返回 404；调用方访问调试接口返回 403；管理员能看到沙箱列表且不含 `lease_id`、能归还他人借用；非回环地址无鉴权时拒绝启动。

### 中

**M1　排队请求在抢沙箱期间不刷新心跳**
- 修复：
  - 心跳改为排队期间常驻的**后台任务**，按 `min(1s, 心跳超时 / 3)` 定期刷新，抢沙箱（包括较慢的恢复）期间照常刷新。心跳任务用事件通知退出，不在数据库操作中途取消。
  - **拿到沙箱时即使排队记录已被判超时，也照常交给请求方**，不再销毁刚恢复好的沙箱；只有客户端已断开时才归还。
- 测试：
  - 恢复耗时 1.5s、心跳超时 0.5s 时，排队请求仍能拿到沙箱。
  - 截止时间在恢复途中到达时，仍返回拿到的沙箱，且没有产生 `lease_failed` 事件。

**M2　借用到期回收可能覆盖刚成功的续期**
- 修复：`cas_lease` 增加「`expires_at <= now`」条件（`expect_expired_at`）。维护循环结束过期借用时带上该条件，续期和回收只有一个能成功。
- 测试：用续期前的借用快照模拟回收，续期后借用仍是 ACTIVE、沙箱仍是 LEASED。

**M3　续期时平台超时设置失败返回 500，且库和平台不一致**
- 修复：
  - 改为**先调用平台 `set_timeout`，成功后再写库**。
  - 平台调用失败时库不变，返回 502（可重试）。
  - 沙箱已不存在时，结束借用并返回 502。
- 测试：注入 `set_timeout` 失败，续期返回 502，借用的 `expires_at` 不变。

**M4　副本在归还后崩溃，占住容量约 `op_timeout` 秒**
- 修复：
  - 归还接口改为**先销毁再返回**：销毁 p99 约 0.4s，崩溃窗口从「整个后台销毁」缩短到「一次 kill 调用」。
  - 截止时间按操作区分：
    - 新增 `POOL_DESTROY_TIMEOUT_S`（默认 30s）和 `POOL_RESUME_TIMEOUT_S`（默认 60s）；
    - 创建、预热、暂停仍用 `POOL_OP_TIMEOUT_S`（120s）。
  - 对应的云端调用都设置了更短的请求超时（kill 20s、恢复 30s + 探活 15s），保证健康的操作不会被误接管。
- 测试：归还返回时云端沙箱已被销毁；kill 失败后的 DESTROYING 记录按 `destroy_timeout_s` 接管，而不是 `op_timeout_s`。

**M5　SQLite 下读操作也拿写锁，吞吐上限低**
- 修复：
  - SQLite 文件库增加**只读连接池**：普通 `BEGIN`，不拿写锁；`PRAGMA query_only` 防止误写。WAL 下读写互不阻塞。写操作仍是每进程 1 个连接 + `BEGIN IMMEDIATE`，保留原来规避锁等待的做法。
  - 顺带减少写操作：
    - 排队心跳从每 200ms 一次降到每秒一次；
    - `expire_waiters` 先查是否有需要清理的排队记录，没有就不发写事务。
  - Postgres 下读写共用普通连接池，不受影响。
- 测试：一个存储实例持有写事务未提交时，另一个存储实例的读查询立即返回，不等 `busy_timeout`。

**M6　E2B 连接句柄缓存只增不减**
- 修复：
  - 句柄缓存改为 LRU + 空闲淘汰：新增 `POOL_HANDLE_CACHE_MAX`（默认 64）和 `POOL_HANDLE_IDLE_TTL_S`（默认 600s）。对应的锁一并清理。
  - 代为执行时发现借用已结束，顺手 `forget` 该沙箱的句柄。
  - 注意：SDK 的连接池（transport）按事件循环共享，淘汰句柄时只丢弃引用，**不能** `aclose`，否则会关掉共享的连接池。
- 测试：缓存按容量和空闲时间淘汰；借用结束后再调用会触发 `forget`。

**M7　创建失败的处理分支本身可能抛异常**
- 修复：
  - 计数键在初始化时预先插入；`kv_set` / `kv_incr` 遇到并发插入冲突时整体重试（走 UPDATE 分支）。
  - 失败处理拆成独立的步骤并**逐步保护**：记事件、累加熔断计数、清理记录和云端沙箱，任何一步出错都不影响后面的步骤。先累加计数再释放名额，熔断在名额释放前生效。
  - 被接管后补杀云端沙箱失败时只记日志，留给对账清理。
- 测试：
  - 初始化后计数键齐全、重复初始化不报错；模拟并发首次插入冲突时，写事务整体重试后成功。
  - 创建失败且熔断计数写入失败时，占用的名额仍被立即释放。

## 5. 接口与数据变化

- 所有 `/v1/*` 接口在开启鉴权后需要 `Authorization: Bearer <key>`。新增错误码：401 未认证、403 需要管理员、413 上传过大、503 池子正在排空。
- 新增 `POST /v1/admin/drain`、`DELETE /v1/admin/drain`；`GET /v1/sandboxes` 仅管理员，不返回 `lease_id`；`/v1/pool/stats` 增加 `pool`、`draining` 等字段。
- 归还接口返回时沙箱已销毁（此前是后台销毁）。
- 数据库新增列 `sandboxes.platform_deadline`、`leases.client_id`，新增索引 `events.ts`，启动时自动补齐；`pool_kv` 新增键 `reconcile_at`、`cleanup_at`、`draining`，启动时预先插入。

## 6. 实施步骤

1. 存储层：只读连接、kv 预置与冲突重试、自动加列、周期任务 CAS、历史清理、暂停前计数、过期条件 CAS、排队位置查询。
2. 后端：句柄缓存 LRU/TTL 与 `forget`、云端调用请求超时；FakeProvider 支持平台超时回收、`set_timeout` / `kill` 失败注入、记录 `list` 调用。
3. 核心逻辑：H1、M1～M4、M7、L4～L7、L9、L10。
4. 接口层：H2、L8、L9 接口与错误码；进程入口的非回环地址保护。
5. 脚本：L1～L3，端到端脚本适配鉴权、新的接管语义，新增排空和 min_hot 保活场景；集群脚本增加 `drain`。
6. 测试：每个问题的针对性用例 + 全量回归。

## 7. 验证计划

1. **单元测试**：全量连续 3 轮通过；新增用例对关键修复（H1、M1、M2、M4、L6）做反向验证：临时去掉修复后用例应失败。
2. **真实云沙箱端到端**（3 副本、第二代模板、开启鉴权）：
   - 原有场景 1～6、6b、8 全部通过；6b 改为验证卡住的沙箱被按实际状态收回。
   - 新增鉴权检查。
   - 新增排空场景：排空后库和云端都为空。
3. **min_hot 保活实测**：以 `POOL_MIN_HOT=2` 和较短的平台空闲超时单独启动集群，超过平台超时后，两个热沙箱仍是原来的 ID、仍在运行，并能直接借出。
4. **收尾**：停止集群，`scripts/cleanup_sandboxes.py` 确认账号下沙箱列表为空；第二代模板保留。

## 8. 取舍与风险

- 归还改为同步销毁后，归还接口多约 0.3s 延迟，换来崩溃时几乎不占容量。
- 接管 PAUSING 时，如果平台查询显示仍在运行，会转为 READY。前提是暂停早已结束或从未发出：接管发生在 `op_deadline`（120s）之后，远大于实测暂停耗时（≤ 17s）。
- 对账、清理由「抢到本周期的副本」执行；该副本在执行中崩溃时，下个周期由其他副本补上。
- 自动加列只处理可空列。更复杂的变更（改类型、加非空列）需要正式的迁移工具。
